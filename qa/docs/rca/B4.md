# RCA B4 : Codes de promotion éternellement actifs
## Symptôme observé
Les codes de promotions restent actifs par delà leur délai maximum prévu.
## Impact 
Pour l'entreprise : une perte d'argent et aucun contrôle sur les code de promotion précédemment émis.
## Preuves (commandes, résultats, capture de la trace, ligne de code)
Voir: la trace dans qa\findings\B4.md
## 5 Pourquoi
| Pourquoi | Réponse | Preuve |
|---|---|---|
| 1. Pourquoi le test UI échoue-t-il ? | Aucun message d'erreur attendu n'apparait, l'API laisse passer un 201 | Voir trace playwright |
| 2. Pourquoi l'API renvoie un code 201 | Sabotage de la guarde sur la date d'expiration des codes promo | Lecture du code au niveau de la validation sur le point d'accès |
| 3. Pourquoi le client a-t-il une réduction | Le code a beau être expiré, il exite toujours dans la DB avec son pourcentage | réponse json apres le 201 de l'api, requete SQL en DB |
## Cause racine
Le formateur a ajouté une variable de bug dans ses conditions et guardes, les faisant passer pour fausse dans certains environnements.
## Actions correctives
### Produit : 
- Ne pas laisser le formateur toucher au code pour un but pédagogique. 
- Enlever en urgences les conditions de vérifications qui peuvent échouer à cause de la variables d'environnement SEED_BUGS="true"
## Comment vérifier que c'est corrigé
Relancer les tests : 
- tests/ui/playwright/test_booking_ui.py::test_expired_promo_code_shows_error
- tests/api/test_booking_rules.py::test_rm4_promo_codes[EXPIRED]
